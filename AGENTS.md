# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project overview

Personal website of Philipp Jauss (`www.philippjauss.gate107.com`). A small,
dependency-light **static PWA** — no framework, no JS library, no build
framework. It is a plain HTML/CSS/JS site compiled by a single Node.js build
script. Content is in **German** (`<html lang="de">`).

Pages: **Home** (photo gallery), **Ich** (`/uebermich`, about), **CV**
(resume + PDF), **Kontakt** (contact).

## Commands

```bash
npm install          # install dev dependencies
npm run build        # full production build into app/
npm run watch        # rebuild on any change under src/ (dev)
npm run serve        # serve the built app/ directory locally
npm run clean        # delete app/
```

Individual build steps (run directly if you only need one):

```bash
node build.mjs clean | css | html | images | static | sw | build
```

There is **no test suite, linter, or type checker** configured. To verify a
change: run `npm run build` (must exit 0), then `npm run serve` and check the
page in a browser.

## Project structure

```
├── src/              # SOURCE — edit here
│   ├── css/site.css  # Main stylesheet (the only CSS you edit)
│   ├── img/          # Source images
│   ├── *.html        # Pages (index, uebermich, cv, kontakt)
│   ├── sw.js         # Service worker source (Workbox)
│   ├── manifest.json # PWA manifest
│   └── .htaccess     # Apache rules (copied to app/)
├── app/              # BUILD OUTPUT — committed, served by the webserver
├── build.mjs         # Build script (the whole pipeline)
└── package.json
```

## Build pipeline (order in `build.mjs`)

1. `clean` — wipe `app/`
2. `css` — copy `site.css` → `app/css/`, then PostCSS/Autoprefixer
3. `static` — copy `.htaccess`, `manifest.json`, `robots.txt`, `sitemap.xml`,
   `favicon.ico`, `cv.pdf`, `cvphilippjauss.pdf`
4. `images` — Sharp: PNG (effort 9), JPEG (q85, progressive), and generate a
   `.webp` (q80) for every jpg/jpeg/png
5. `html` — Cheerio inlines CSS/JS, then `html-minifier-terser` minifies
6. `sw` — Workbox `injectManifest` bakes the precache list into `sw.js`

## Important gotchas

- **`app/` is committed on purpose.** The production Apache server serves
  `app/` directly. Do **not** add `app/` to `.gitignore`. After changing
  anything in `src/`, you must `npm run build` **and commit the regenerated
  `app/`**, or the live site will not update.
- **Edit `src/css/site.css`.** It is the single source of truth for all styles
  (plain CSS, no preprocessor). The build copies it to `app/css/site.css` and
  inlines it into each page.
- **CSS inlining is opt-in via the `inline` attribute.** The build only inlines
  a stylesheet if its `<link>` tag carries the `inline` attribute
  (`<link inline rel="stylesheet" href="/css/site.css" />`). Removing `inline`
  leaves it as an external request.
- **There is no `src/js/` directory.** All JavaScript (the service-worker
  registration) is written inline in each HTML page. The build's JS-inlining
  step is effectively a no-op today.
- **Image pattern.** Reference images with a `<picture>` block: a `.webp`
  `<source>` first, then a fallback `<source>`, then the `<img>`. The `.webp`
  is generated by the build — do not hand-add it to `src/img/`.
- **URLs are extensionless.** Apache (`src/.htaccess`) rewrites `/cv` →
  `cv.html` and 301-redirects `/cv.html` → `/cv`. Link to `/uebermich`, `/cv`,
  `/kontakt`, `/` — never to `*.html`.

## Conventions

- Indent: **4 spaces**; line endings **LF**; encoding **UTF-8**; final newline
  (see `.editorconfig`).
- Vanilla HTML/CSS/JS only. Do not introduce frameworks, bundlers, or new
  runtime dependencies without being asked.
- Keep the PWA intact: service worker (`sw.js`), `manifest.json`, and the
  `theme-color` meta (`#0046a0`).

## Adding content

- **New image:** drop the file in `src/img/`, reference it in a `<picture>`
  block (webp source + fallback + img), rebuild.
- **New page:** add `src/<name>.html` following the existing page structure
  (same `<head>`, nav with the correct `active` link, service-worker
  registration script), then rebuild. Remember to add it to the nav on every
  page and to `sitemap.xml`.

## Deployment

Apache serves the `app/` directory. `src/.htaccess` (copied to `app/.htaccess`)
configures short cache expiry (1 minute) and the extensionless-URL rewrites.
Deployment = commit the rebuilt `app/` and push; the server picks it up from
there.
